# Публичная версия

Открытый комплект содержит только файлы из `publication_manifest.json`. Добавление файла в Git не означает разрешения раскрыть данные. Скрипт `scripts/check_publication.py` проверяет рабочие кандидаты, а с `--index` - именно содержимое подготовленного индекса Git.

## Что остается закрытым

Каталоги `data/`, `reports/`, `.local/`, `tmp/`, обученные модели, исходные и обработанные базы, индивидуальные прогнозы и значения SHAP, рабочие документы больницы. Их нельзя включать в публичный релиз даже после удаления ФИО. Не следует публиковать полный выполненный ноутбук.

Публичные таблицы содержат агрегаты. Они отобраны из готовых результатов и проверены отдельно. Их список, структура и контрольные суммы позволяют обнаружить случайную подмену на пациентскую таблицу. Это техническая защита от ошибок упаковки, а не автоматическое доказательство анонимности любых новых материалов.

## Локальная работа

Публичный `notebooks/pipeline.ipynb` хранится без выходов. `scripts/run_analysis.py` сохраняет выполненную копию в игнорируемом `reports/`. Перед подготовкой публикации исходная рабочая версия с выходами сохранена локально в `.local/before_publication_cleanup_2026-11-04/`. Флаг `skip-worktree` снят: изменения исходного ноутбука больше не скрываются от Git.

Старые рукописи, комментарии, исходники журналов и промежуточные PDF сохранены локально и исключены из публичного состава. Публичные копии названы `paper/manuscript_ru.*`. Согласованный научный текст при подготовке репозитория не менялся.

## Проверка перед коммитом

```bash
python -m unittest discover -s tests -v
ruff check src scripts tests paper/make_figures.py
python scripts/check_publication.py
```

После просмотра изменений подготовить разрешенные файлы к коммиту и выполнить `python scripts/check_publication.py --index`. В CI эта же логика проверяет состав коммита. GitHub Actions не запускает клинические расчеты и не получает закрытый датасет.

После изменения согласованного PDF, сводной таблицы или текста рукописи нужно повторно проверить материал и явно обновить соответствующую контрольную сумму. Не следует автоматически обновлять все суммы, чтобы скрыть ошибку проверки.

## Выпуск

`python scripts/package_release.py` создает проверенный ZIP в `.local/releases/`, ничего не отправляя в сеть. Архив не содержит базы или моделей. После утверждения состояния можно создать коммит, тег и релиз GitHub. DOI и ссылку на опубликованную статью добавляют только после их фактического получения. Поле этического одобрения в рукописи остается открытым до ответа больницы.

Для дополнительной архивной копии кода можно использовать хранилище, выдающее DOI, но загрузка материалов туда не выполняется автоматически. Лицензия MIT относится к коду, а не к медицинским данным и не к стороннему шаблону журнала.
